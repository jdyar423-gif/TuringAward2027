# Data sources, downloads and token shards

Registry: `bes/data/sources.py`. Downloads: `bes/data/download.py`. Shard format:
`bes/data/shards.py`. Tokenisation pool: `bes/data/tokenize_worker.py`. Tests: `tests/data/`.

## 1. How the registry was verified (2026-11-21)

For every entry: `https://huggingface.co/api/datasets/<id>` (commit sha, card licence, gating),
the repository tree at that commit (paths, sizes, LFS sha256), the datasets-server `splits`,
`info` (features, row counts) and `first-rows` endpoints, and the dataset card text for licence
details. Where datasets-server failed or was too slow, the parquet footer and the first batches
were read with range requests (`HfFileSystem` + pyarrow). The recorded example rows are the
test fixtures in `tests/data/fixtures/<source>.json` (strings shortened, licence noted).

`tests/data/test_tokenize_worker.py::test_registry_listings_match_the_hub` (marked `net`, ~3 s)
re-lists every entry and asserts the file count and, at pinned commits, the exact byte total.
All 26 entries matched on 2026-11-21.

Main-branch datasets are pinned to the verified commit (`revision = verified_sha`). Datasets
whose main branch is JSON use the datasets-server parquet conversion `refs/convert/parquet`;
that ref is kept as the revision (conversion branches are regenerated by the Hub) and the
commit seen at verification is recorded in `verified_sha`. The first listing of a source in a
`data_cache` resolves the revision to a commit and caches it, so file indices stay fixed.

## 3. Adapters (one parquet row -> text, conversation or pair)

Adapter output is exactly `bes.data.chat_format` input: roles `system | user | assistant |
library`, turn grammar `[system] ([library] user assistant)+` (`clean_messages` enforces it and
drops trailing turns after the last assistant turn). chat_format allows **one** library turn
before a user turn, so several passages are joined into one library turn with `PASSAGE_SEP`
(`"\n\n---\n\n"`), each passage title first, at most `MAX_PASSAGES = 3`, each capped at 6,000
characters. Calculator spans are assistant content parts `{"type": "calc", "expr", "result"}`.

- **Base text**: `text` (ClimbMix, FineWeb-Edu); `title + "\n\n" + text` (Wikipedia).
- **SmolTalk family, UltraChat**: `messages` as is (cleaned).
- **Tulu 3**: drops the `source` subsets in `TULU_EXCLUDED`: `no_robots_converted` (CC BY-NC
  4.0), `tulu_v3.9_aya_100k` (non-English), `tulu_hard_coded_repeated_10` (identity answers
  naming another model) — 109,740 rows.
- **SYNTH closed book** (`synth`): English rows of exercises memorization, mcq, math exercise,
  constrained writing, creative writing, cooking: `query` -> `synthetic_answer`; the reasoning
  draft is dropped. Memorization rows are split in two disjoint halves by CRC-32 of `synth_id`;
  the odd half goes to the open-book entry.
- **SYNTH open book** (`synth_rag`): odd-half memorization rows with the seed section as the
  passage (title from `query_seed_url`), and `rag` exercise rows with the `<source_k>` blocks
  that the answer cites (plus one uncited distractor); `<ref …>…</ref>` citations are removed.
- **glaive_rag**: cited documents (+1 distractor) as passages; the `Cited Documents:` header,
  `Answer:` prefix and `<co:k>` tags are removed; the system prompt (identical on every row) and
  the `answer_mode` field are dropped. Rows citing no document keep the first one as distractor.
- **rag_instruct**: 10 untitled documents per question and no supporting labels; the 3 with the
  largest overlap of distinct >= 4-character words with the answer are kept (a heuristic).
- **neural_bridge_rag**: `context` -> passage. **squad_v2**: `title` + `context` -> passage;
  first answer span, or `SQUAD_UNANSWERABLE` ("The passage does not contain the answer to this
  question.") for the unanswerable third. **hotpot_qa**: supporting paragraphs + the first
  distractor in native order. **dolly**: `context` -> passage when present.
- **gsm8k**: every `<<expr=result>>` becomes one calculator part; the visible copy of the
  result after it and an equal visible `expr =` before it are removed (`gsm8k_calc_text`);
  `#### N` -> `The answer is N.`; trailing decimal zeros of results trimmed (`144.00` -> `144`);
  results are not re-evaluated. On the 7,473 train solutions: 23,713 of 23,716 annotations kept;
  the displayed text (`expr = result`) equals the original visible text for 4,873 solutions,
  adds a restatement of the expression for 2,426 (the original wrote it differently, e.g.
  `12 x 2` or `6 jaguars`), and differs only by trimmed zeros for 174.
- **tinygsm**: the program as a fenced python block (weight 0, see section 4).
- **orca_math**: question -> answer. **ultrafeedback**: `Pair(chosen, rejected)`, ties dropped.

## 4. What did not check out, and caveats

1. **ClimbMix licence.** `karpathy/climbmix-400b-shuffle` says MIT, but its upstream
   `nvidia/Nemotron-ClimbMix` is CC BY-NC 4.0; the entry is marked non-permissive with
   `fineweb_edu` as fallback. The datasets-server `info`/`parquet` endpoints fail for this repo;
   the schema (one `text` column, 84 row groups of 1,024 rows per shard) was read from the files.
2. **SmolTalk** has no licence field in its YAML header; the card text says the new subsets
   (Magpie-Ultra, constraints, rewrite, summarize) are Apache 2.0 and the others follow their
   upstream (both checked: Apache 2.0). Smol-Magpie-Ultra was generated by a third-party model
   whose licence sets conditions on the use of its outputs (see the card).
3. **Tulu 3**: "some portions are non-commercial" (No Robots) — excluded; contains outputs of
   third-party models; the subset `tulu_v3.9_open_math_2_gsm8k_50k` is present in the data but
   not listed on the card.
4. **PleIAs/SYNTH exists and is usable**, with care: 500 files, each **one row group of
   ~795 MB** (the streaming reader keeps memory flat, see section 5). In the datasets-server
   statistics (first ~1.09 M rows) ~19% of rows are not English and 90.6% are memorization. In a
   41k-row sample of `synth_001.parquet`: `editing` answers are sometimes cut off after one
   sentence (excluded); `math mcq` answers are bare letters (excluded); rows whose `query_seed_url`
   is the label `"Pleias self-knowledge"` (0.5% of the sample) **answer in the first person as
   the dataset authors' own models** and are dropped. Card licence CC BY 4.0,
   seed texts CC BY-SA 4.0 (column `seed_license`). The datasets-server `filter` endpoint was
   unavailable (index loading), hence the direct sampling.
5. **glaive RAG-v1, RAG-Instruct, Dolly** are single JSON / JSONL files on their main branch;
   the parquet conversion is used. RAG-Instruct was synthesised by a third-party model (card).
6. **neural-bridge** asks users to also abide by the terms of use of the web corpus it was
   drawn from.
7. **TinyGSM** has a minimal card (licence MIT, no provenance). Its answers are Python programs;
   the model has a calculator, not an interpreter, so the default weight is 0 until a
   program -> calculator-span converter exists.
8. **Synthetic-output provenance**: per their cards, Orca-Math answers, UltraChat dialogues and
   the UltraFeedback scores were generated by third-party proprietary models, whose terms of use
   may restrict training on their outputs; the cards name the models.
9. **UltraFeedback** contains ties (4 of the first 27 rows have equal scores); they are dropped.
10. **SmolTalk everyday-conversations**: 13 of the first 100 dialogues end with a user turn
    (that turn is dropped).

## 5. Files on disk

Under `RunCfg.data_dir` (`data_cache/`, git-ignored):

```
raw/<org>__<name>/<rev>/<path in repo>        downloaded files (atomic rename)
raw/<org>__<name>/<rev>/manifest.jsonl        {"repo","commit","path","size","sha256","time"}
raw/<org>__<name>/<rev>/listing.<prefix>.json cached listing + resolved commit
tok/<source>/<n>.u16 / .idx / .role / .rec    shards (n = index of the input file)
tok/<source>/manifest.jsonl                   one line per committed shard
```

- **Downloads**: files are taken in listing order up to `max_files` / `max_bytes` (the first
  file always), fetched with `hf_hub_download` into a staging directory, checked (size, LFS
  sha256), fsynced, renamed, then recorded. Retries: exponential backoff (2 s doubling, capped
  at 60 s, jittered, 6 attempts); missing repository / revision / file is not retried. Per-file
  locks make threads and processes safe; a file renamed but not yet recorded is verified and
  recorded on the next call. Byte-level resume of a partial file is left to huggingface_hub and
  was not verified (a restart re-fetches at most the files in flight; one 94.5 MB file took
  2.8 s here).
- **Shards** (`bes-shard/1`): `.u16` uint16 ids (every segment starts with BOS, BOS nowhere
  else); `.idx` int64 offsets `[n_segments + 1]`; `.role` int8 role code per token (from
  chat_format; conversations only); `.rec` int64 input row per segment. One input file -> one
  shard, so output is independent of the number of workers. Conversations are stored whole —
  truncation at turn boundaries (`chat_format.truncate_to_turns`) is the loader's job. A
  preference pair is two consecutive segments (chosen, rejected) with the same `.rec`; such
  shards have `"pairs": true`. The manifest entry carries sizes and CRC-32 of every file, the
  input file (repo, commit, path, sha256), the tokenizer fingerprint (asset sha256), a code
  fingerprint, counters and timing. `shards.check(dir)` verifies all of it.
- **Commit protocol**: workers write temporaries with unique names, fsync, rename and fsync the
  directory; only the coordinator appends the manifest line, after that. Restarting skips
  committed shards and redoes the rest; a torn manifest tail is ignored and cut by the next
  append. Workers receive SIGKILL when the coordinator dies; a dead worker fails its files
  instead of hanging the run.
