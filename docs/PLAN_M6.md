# 六小時任務計畫：讀者＋藏書（`configs/m6.py`）

任務：在 **TPU v6e-1、總配置時間 ≤ 6 小時** 內，從零訓練一個**總參數 ≤ 100M、每 token 活躍 ≤ 20M** 的模型，主觀對話品質要勝過 Falcon-H1-Tiny-90M-Instruct。本文件寫於開跑之前，是這次執行的事前登記：設計、數學依據、時間表、評測方式與誠實的預期。結果另寫在 `docs/CHANGES.md` 與論文，不回頭改這裡的預期。

## 1. 起點：六小時買得到什麼

| | 訓練 token | 來源 |
|---|---|---|
| Falcon-H1-Tiny-90M-Instruct | 約 8×10¹¹ | TII 部落格（訓練語料 800 GT） |
| 本專案 24 小時（`configs/v9.py`） | 1.36×10¹⁰ | `docs/CHANGES.md` 19.x |
| 本任務六小時 | 約 5×10⁹（2.66×10⁵ tok/s × 約 1.9×10⁴ s） | 晶片上量過的 `final` 核心速率 |

六小時的 token 數是 Falcon 的 1/160、上一輪的 37%。上一輪的官方模型對 Falcon 的盲測得分是 0.318（Opus 兩讀）、登記評審 12 勝／61 平／127 負。**單靠「再訓一次、更短」不可能反超**，所以這一輪改變的是「100M 個數字裡，哪些用訓練填、哪些用寫的填」。

## 2. 數學依據：寫進去的記憶比訓練出來的記憶密一個數量級

計帳規則（`docs/ACCOUNTING.md`）：一個參數＝一個隨模型出貨、至多 16 位元的數字；活躍＝產生一個 token 時讀到的相異數字。規則只限制**個數**與**讀取量**，不限制數字怎麼來。

**(a) 訓練出來的數字。** 文獻量到的容量是每個參數約 2 位元（Allen-Zhu & Li, 2024, *Knowledge Capacity Scaling Laws*）到 3.6 位元（Morris et al., 2025, *How much do language models memorize?*），而且前者指出要達到這個容量，一則知識需要上千次曝光。80M 個「不活躍」的訓練參數因此至多存 1.6–2.9×10⁸ 位元（20–36 MB），而六小時裡絕大多數事實只出現一次，連這個上限都到不了。上一輪的做法（逐詞頁、查表）正是把不活躍的 80M 交給梯度，24 小時也只換到有限的收益。

**(b) 寫進去的數字。** 一個 16 位元的數字若直接存壓縮文字，就是 16 位元的資訊，不需要任何曝光。本任務的藏書實測：

| 項目 | 數值 |
|---|---|
| 問答對 | 399,699 |
| 原始文字 | 340,394,591 位元組 |
| 儲存數（文字塊＋目錄＋逐筆資料＋索引） | 57,424,740 |
| 每個儲存數承載的原文 | 5.93 位元組 |

也就是：同樣 5,700 萬個數字，寫入的方式存下 340 MB 的**教師模型原文**；用訓練的方式，理論上限約 14–26 MB 的資訊量，而且六小時內到不了。兩者差一個數量級以上，並且寫入不花任何 TPU 時間。

**(c) 推論。** 把預算拆成兩種角色：

- **讀者**（34,531,720 個訓練出來的數字，每 token 讀 19,033,736）：只學「語言、對話、照著範例作答、用計算機」這些**技能**，不背知識。核心沿用上一輪在晶片上調好的 `final`（稠密迴圈核心、候選帶、暫存器），所以六小時全數用在訓練，不花在重新調速。
- **藏書**（57,424,740 個寫入的數字，每則回覆至多讀 700,000）：存教師寫好的答案，推論時查。

合計 91,956,460 ≤ 100M；每 token 活躍 19,733,736 ≤ 20M（把單則回覆的藏書讀取上限**全部**記在同一步上；上限由讀取記錄強制執行，不是估計值；`tests/model/test_config_budgets.py`）。

## 3. 系統定義

令 x 為使用者訊息，L = {(qᵢ, aᵢ)} 為藏書。回覆分佈為

```
p(y | x) = 1[v(x) ≠ ∅] · δ(y = a_v(x))  +  1[v(x) = ∅] · p_θ(y | E(x), x)
```

- **比對分數。** 詞項取去停用詞、去複數後的詞；idf(t) 由 2²⁰ 個雜湊桶的文件頻率給出。
  cov_q = Σ_{t∈x∩q} idf(t) / Σ_{t∈x} idf(t)，cov_e = Σ_{t∈x∩q} idf(t) / Σ_{t∈q} idf(t)，sym = min(cov_q, cov_e)。
  索引先用倒排表取部分分數最高的 12 筆，再讀出問題原文、以**詞項字串**算精確分數（雜湊碰撞不會造成誤配）。
- **原文層 v(x)。** 同時滿足：問題類型相同、cov_q ≥ 0.8、cov_e ≥ 0.55、兩邊各自沒有 idf > 5 的獨有詞（「字典」不等於「字典推導式」）、沒有對比詞衝突、存的答案通過使用者訊息裡明寫的格式限制（由限制編譯器驗證）。成立時，回覆就是存的答案，逐字給出。
- **範例層 E(x)。** sym ≥ 0.5（算術題 0.75）的最佳一筆，加上至多一筆 sym ≥ 0.6 的次佳；訊息的句子與逗號後半句也各自查一次（分數 ×0.9）。範例以 `Q: … / A: …` 放在使用者回合之前的 LIBRARY 回合，答案截到 1,400 字元。
- **讀者 p_θ。** 與上一輪相同的 Feynman–Kac 粒子解碼（K = 6）、精確位勢（格式限制）、計算機段與選擇器。
- **不查的情況。** 超過 1,000 字元的訊息（那是文件，不是問題）、依賴前文的後續回合。
- **讀取上限。** 一則回覆的所有查詢（原文層、整句、各子句）共用一份讀取記錄；倒排表或文字塊若會使累計超過上限就不讀。

開發集 200 題（第一回合）在定稿藏書上的覆蓋，僅作設計依據，不是成績：

| 類別 | 題數 | 原文層 | 範例層 | 無 |
|---|---|---|---|---|
| chat | 50 | 7 | 32 | 11 |
| code | 30 | 4 | 18 | 8 |
| instruct | 40 | 1 | 18 | 21 |
| math | 30 | 0 | 1 | 29 |
| writing | 50 | 1 | 10 | 39 |
| 合計 | 200 | 13 | 79 | 108 |

## 4. 訓練

1. **從零開始、全程 2,048 token 列。** 對話佔 90%（85% 進度後 95%），底層文字 5–10%。新增教師寫的對話來源（Magpie-Llama-3.1、Magpie-Phi3、OpenHermes-2.5、gpt4all-j、glaive-code、WizardLM、Alpaca、CodeAlpaca；`docs/DATA_SOURCES.md`）。最後 15% 只對助理 token 算損失。
2. **照推論的方式訓練讀範例。** 每筆對話以 0.9 的機率走一次與推論相同的檢索：以它的第一個使用者訊息查藏書，**排除與它自己同題的條目**（留一法，否則模型學到的是抄答案），查得到就把範例放進 LIBRARY 回合。5% 換成不相干的條目，讓模型學會忽略沒用的範例。範例 token 的損失權重 0.25。彩排實測約 36% 的對話問題查得到範例。
3. **事後計算機標註。** 上一輪 24 題算術錯題裡有 6 題是單純算錯。現在助理回合裡每一句「算式 = 數字」，只要算式在計算機的語言內、且寫的結果與計算機的結果**完全相等**，就改寫成計算機段 `CALC 算式 EQ 結果 CALC_END`；推論時結果由主機算出，不由模型產生。四捨五入過的、寫錯的、含單位或百分號的都不動。orca-math 有 36.7% 的答案至少得到一個計算機段。
4. **評測題不進訓練、不進藏書。** 評測集（開發＋測試共 400 題）每一個使用者回合，正規化後若與某筆訓練對話的使用者回合相同，那筆對話整筆丟掉；藏書建置時同樣剔除（54 筆）。
5. **訓練後。** 只做偏好最佳化（DPO，單一學習率 3×10⁻⁶，UltraFeedback）與匯出；DPO 前的權重也保存。

## 6. 評測（先登記）

- 對手：Falcon-H1-Tiny-90M-Instruct，官方建議設定，同一批 200 題測試題（上一輪已生成的回覆沿用）。
- 評審：登記的自動評審 qwen3-4b-2507，兩種左右順序各評一次；另報精確分數（算術正確率、格式限制達成率）。本任務不使用子代理評審。
- 同時回報：藏書開／關、原文層回覆的佔比與其單獨勝率、各類別、K = 1。
- 門檻類設定（原文層與範例層的閾值、是否啟用原文層）只在開發集上調，測試集只跑一次。

## 7. 誠實的預期與風險

- 可以預期的改善：約 46% 的開發題有教師原文或教師範例可用（chat 78%、code 73%）；算術不再因為算錯而失分；訓練分佈幾乎全是對話。
- 做不到的：六小時的讀者比上一輪的模型看過的文字更少，沒有範例的題目（寫作 78%、數學幾乎全部）要靠它自己；這些題上輸給 Falcon 的機會仍然高。
- 整體預期是**與 Falcon 接近到小幅領先**，「遠超」不保證。若結果不如預期，照實回報。
- 風險：原文層答非所問（閾值偏嚴，並在開發集上檢查）；模型過度依賴範例（5% 干擾項、留一法）；執行階段被收回（快照與續訓）。

## 8. 與近期工作的關係

- **Engram**（DeepSeek, arXiv 2601.07372）與 **Memory Layers at Scale**：以雜湊鍵查詢**訓練出來的**嵌入表，查表列不經過注意力。本設計同樣是「雜湊查詢、每步只讀少量」，但表裡放的是**寫入的文字**而非訓練出的向量：不需要梯度曝光，內容可檢查、可更新、可逐條標示出處。
- **Falcon-H1-Tiny**：反課程（從一開始就混入對話）、Muon、DPO。本任務同樣從第一步起以對話為主，並沿用上一輪的 MuonH 與 DPO。
- 與一般 RAG 的差別在計帳：藏書計入 100M 的總量、每則回覆的讀取量計入 20M 的活躍量，並由測試強制；它是模型的一部分，不是外掛資料庫。
